# 11 - 内存分段

基址-边界机制给整个地址空间配一对寄存器，但真实程序的地址空间很"稀疏"——栈和堆中间往往隔着一大段没用到的空档。空档也要在物理内存里占地方，这就浪费了。分段就是为了解决这个问题：不再管"整个地址空间"，而是给**每个逻辑段**（代码、堆、栈）单独配一对基址-边界寄存器。

## 一、基本思想：每个段一对基址-边界

为每个**逻辑段**（代码、堆、栈）各自独立分配一块连续物理内存，各自有自己独立的基址（物理起始地址）和边界（大小）寄存器。栈和堆之间的空档就不用再分配物理内存了，地址空间可以又大又稀疏。

![alt text](../assets/11_1-在物理内存中放置段.png)

举个例子：地址空间 0-16KB 里，代码段占 0-2KB，堆占 4-7KB，栈占 14-16KB（中间 2-4KB、7-14KB 是空的）。分段的物理分配是：

| 段类型 | 基址 | 大小 | 增长方向 | 权限 |
|--------|------|------|----------|------|
| 代码段 | 32KB | 2KB | 正向 | 读-执行 |
| 堆 | 34KB | 3KB | 正向 | 读-写 |
| 栈 | 28KB | 2KB | 反向 | 读-写 |

这些段在物理内存里的摆放示意（栈基址 28KB、反向增长，实际占用 26~28KB）：

```text
  0 KB ┌──────────┐
       │   空闲   │
 26 KB ├──────────┤ ← 栈（2KB，基址 28KB，向下长）
       │   栈     │
 28 KB ├──────────┤
       │   空闲   │
 32 KB ├──────────┤ ← 代码段（2KB）
       │  代码段  │
 34 KB ├──────────┤ ← 堆（3KB）
       │   堆     │
 37 KB ├──────────┤
       │   空闲   │
 64 KB └──────────┘
```

三个段加起来只占 6KB 物理内存，而不是 16KB 的完整地址空间。

## 二、地址翻译

翻译分两步：先判断虚拟地址属于哪个段，再算出段内偏移，最后加上该段的基址。

判断段有两种方式：

- **显式方式**：用虚拟地址的高位比特标段。比如 14 位地址取前 2 位：00→代码、01→堆、11→栈；剩下的低位就是段内偏移。需满足“偏移 < 段大小”（边界检查），否则触发段错误（Segmentation Fault）。
- **隐式方式**：看地址是哪来的——程序计数器（PC）产生的地址去代码段，栈指针（SP）的去栈段，其余去堆。

![alt text](../assets/11_2-显示方式.png)

翻译示例（沿用上面的寄存器配置）：

| 示例 | 判断段 | 段内偏移 | 物理地址计算 | 结果 |
|------|--------|----------|--------------|------|
| 虚拟地址 100 | 高位 00 → 代码段 | 100（< 2KB，合法） | 32KB + 100 | 32868 |
| 虚拟地址 4200 | 落在堆段（起始 4096） | 4200 − 4096 = 104 | 34KB + 104 | 34920 |
| 虚拟地址 15KB | 落在栈段（反向增长） | 正向偏移 15KB − 14KB = 1KB，转负 = 1KB − 2KB = −1KB | 28KB + (−1KB) | 27KB |

### 栈的反向增长

栈向低地址长，和代码段、堆方向相反，需要硬件额外支持：用段寄存器里的**增长方向位**区分（1=正向，0=反向）。关键区别在于：**基址指的是栈的顶端（高地址那一端），不是栈底**。

翻译栈地址 15KB 分三步：

1. **判断段**：栈占地址空间里的 14~16KB，15KB 落在里面；
2. **算负偏移**：先按栈底（14KB）量出正向偏移 `15KB − 14KB = 1KB`，再转负 = `1KB − 段大小(2KB) = −1KB`——因为基址在顶端，得往回数；
3. **加基址**：物理地址 = `28KB（基址，栈顶）+ (−1KB) = 27KB`。

对照映射关系（栈顶对齐基址）：

```text
栈顶 16KB  →  基址 28KB（顶端）
15KB       →  28KB − 1KB = 27KB
栈底 14KB  →  28KB − 2KB = 26KB
```

一句话：正向增长的段（代码/堆）基址在低端、偏移直接加；反向增长的段（栈）基址在**高端**、偏移要取负、从顶端往回减。

![alt text](../assets/11_3-段寄存器.png)

### 段错误（Segmentation Fault）

遇到下面任一种，硬件触发异常、OS 终止进程：
- 高位比特指向无效段；
- 段内偏移 ≥ 段大小；
- 访问权限不匹配（比如写只读代码段）。

## 三、共享与保护

- **保护位（Protection Bits）**：每个段配上读/写/执行权限，翻译时顺便检查。代码段只读+执行（防篡改），堆/栈读+写（禁止执行，防注入）。越权就异常。
- **代码共享**：代码段设为只读+执行后，可以让多个进程把它映射进各自的地址空间，共享同一块物理内存——省内存，又不破坏隔离（反正谁都改不了）。

![alt text](../assets/11_4-段寄存器2.png)

## 四、OS 要干什么

1. **上下文切换**：保存当前进程所有段寄存器的值（基址、大小、权限）到 PCB，恢复下一个进程的。
2. **段增长管理**：堆/栈要扩容时（`malloc`/`sbrk`），OS 检查有没有空闲物理内存，有就更新段大小寄存器，没有就拒绝。
3. **空闲管理**：段大小可变，频繁分配/释放后物理内存会出现**外部碎片**——总空闲够，但都是不连续的小块，塞不下一个大段。解决办法是内存紧凑（暂停进程、把段拷到连续区、改基址、合并空洞，代价大），或者靠首次适配/最佳适配等空闲列表算法（只能缓解，不能根治）。

![alt text](../assets/11_5-非紧凑和紧凑的内存.png)

## 五、分段的短板

1. **外部碎片**是最大问题；
2. **灵活性不够**：只能按固定的几个逻辑段分，扛不住更稀疏的地址空间（比如多个离散数据段）；
3. **段大小受限**：显式方式下，段大小由高位比特数决定（2 位标段 → 每段最多 4KB），不好扩容。

## 六、总结

1. 分段的价值：解决稀疏地址空间的浪费，支持代码共享和权限保护，翻译靠硬件直接算、很高效。
2. 代价是引入外部碎片，而且灵活性仍被固定逻辑段限制。
3. 这些缺陷催生了分页（Paging）——把地址空间和物理内存都切成固定大小的页，彻底解决外部碎片。

## 七、作业方向（Simulation）

通过 `homework/vm-segmentation/segmentation.py` 模拟两段式地址翻译：地址空间从中间一分为二，低半段是段 0（正向增长，如代码/堆），高半段是段 1（负向增长，如栈）。`-A` 指定访问地址序列，`-b/-l/-B/-L` 指定两段的基址/边界，`-c` 看答案。

1. 给定地址空间和物理内存参数，计算虚拟地址→物理地址的翻译结果；
2. 配置基址-边界参数，生成指定的“合法/非法”地址序列；
3. 调整参数使90%的随机虚拟地址合法，或全部非法；
4. 验证栈反向增长、权限检查的翻译逻辑。

### 1. 默认参数的地址翻译

```shell
./segmentation.py -s 0 -c
```

```text
Segment register information:
  Segment 0 base  (grows positive) : 0x00001aea (decimal 6890)
  Segment 0 limit                  : 472
  Segment 1 base  (grows negative) : 0x00001254 (decimal 4692)
  Segment 1 limit                  : 450
Virtual Address Trace
  VA  0: 0x0000020b (decimal:  523) --> SEGMENTATION VIOLATION (SEG1)
  VA  1: 0x0000019e (decimal:  414) --> VALID in SEG0: 0x00001c88 (decimal: 7304)
  VA  2: 0x00000322 (decimal:  802) --> VALID in SEG1: 0x00001176 (decimal: 4470)
  VA  3: 0x00000136 (decimal:  310) --> VALID in SEG0: 0x00001c20 (decimal: 7200)
  VA  4: 0x000001e8 (decimal:  488) --> SEGMENTATION VIOLATION (SEG0)
```

asize = 1k = 1024，用地址的最高位分两段，各占一半，所以分界点 = `1024 ÷ 2 = 512`：最高位是 0（`VA < 512`）进段 0（正增长），最高位是 1（`VA ≥ 512`）进段 1（负增长）。逐条看：

- VA 414 < 512 → 段 0，且 414 < 472 → `6890 + 414 = 7304` ✓
- VA 310 → 段 0，310 < 472 → `6890 + 310 = 7200` ✓
- VA 488 → 段 0，但 488 ≥ 472 → VIOLATION（段 0 越界）✗
- VA 802 ≥ 512 → 段 1，802 ≥ 1024−450=574 → `4692 + (802−1024) = 4692 − 222 = 4470` ✓
- VA 523 ≥ 512 → 段 1，但 523 < 574 → VIOLATION（段 1 越界）✗

### 2. 用寄存器点杀特定地址

用 `-A` 指定确切 VA、`-l 400` 把段 0 边界设成 400，就能精确控制哪些 VA 合法：

```shell
./segmentation.py -a 1k -n 5 -A 100,399,400,511,600 -l 400 -b 100 -L 50 -B 1000 -c
```

```text
  Segment 0 base  (grows positive) : 100
  Segment 0 limit                  : 400
  VA  0: 100  --> VALID in SEG0: 200    ← 100 < 400，100 + 100 = 200
  VA  1: 399  --> VALID in SEG0: 499    ← 399 < 400，399 + 100 = 499
  VA  2: 400  --> SEGMENTATION VIOLATION (SEG0)   ← 400 正好踩线
  VA  3: 511  --> SEGMENTATION VIOLATION (SEG0)   ← 511 ≥ 400
  VA  4: 600  --> SEGMENTATION VIOLATION (SEG1)   ← 段 1 边界 50 太小，600 < 1024−50
```

边界就卡在 VA=400 这条线上：VA < 400 合法、VA ≥ 400 越界。段 1 同理，边界 50 只放行最顶上的 50 个地址，600 够不着。

### 3. 让 90% 合法 / 全部非法

地址空间对半分，每段占半空间。某段合法比例 ≈ 该段边界 / 半空间，所以要 90% 就把边界设成"半空间 × 0.9"，要全非法就设 0、全合法就设半空间大小：

```shell
./segmentation.py -a 1k -p 64k -n 2000 -s 0 -l 460 -L 0 -b 0 -B 32768 -c    # 段0 90% 合法
./segmentation.py -a 1k -p 32k -n 5   -s 0 -l 0   -L 0 -b 0 -B 1024 -c      # 全非法
./segmentation.py -a 1k -p 64k -n 10  -s 0 -l 512 -L 512 -b 0 -B 32768 -c   # 全合法
```

```text
# -l 460: 段0 的 999 个随机 VA 里 892 个 VALID（约 89%，≈ 460/512）
# -l 0 -L 0:     5 个 VA 全部 SEGMENTATION VIOLATION
# -l 512 -L 512: 10 个 VA 全部 VALID（段0 PA=VA，段1 用 32768 做基址）
```

### 4. 段 1 反向增长的负偏移

段 1 基址 4692 指向"栈顶"（虚拟地址 1024 对应的位置）、负向增长。用 `-A` 指定几个段 1 地址，看 `PA = 4692 + (VA − 1024)` 怎么走：

```shell
./segmentation.py -a 1k -n 4 -A 1023,900,640,600 -l 0 -b 0 -L 512 -B 4692 -c
```

```text
  Segment 1 base  (grows negative) : 4692
  Segment 1 limit                  : 512
  VA  0: 1023 --> VALID in SEG1: 4691   ← 4692 + (1023−1024) = 4692 − 1
  VA  1: 900  --> VALID in SEG1: 4568   ← 4692 + (900−1024)  = 4692 − 124
  VA  2: 640  --> VALID in SEG1: 4308   ← 4692 + (640−1024)  = 4692 − 384
  VA  3: 600  --> VALID in SEG1: 4268   ← 4692 + (600−1024)  = 4692 − 424
```

VA 越靠近栈顶（1024），`VA−1024` 负得越少，PA 越接近基址 4692；VA 越往栈底，负得越多，PA 越低。所以"栈向低地址长"体现在：VA 减小，PA 也跟着减小。

（注：模拟器只做地址翻译和越界判断，不检查读/写/执行权限位；权限位属于硬件保护，翻译逻辑里体现不到。）
