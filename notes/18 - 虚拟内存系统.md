# 18 - 虚拟内存系统

前面各章是"零件"：分页、TLB、多级页表、置换策略。这一章把它们装成两台真实的机器——经典的 **VAX/VMS**（1970s-1980s）和现代的 **Linux**，看一个完整 VM 系统怎么把这些机制组合起来，还要兼顾性能、安全和复杂度。

## 一、经典案例：VAX/VMS

VAX/VMS 是早期 VM 系统的标杆，核心思路是"用软件创新弥补硬件缺陷"（比如它只有 512 字节小页、又没有引用位）。

### 1. 地址空间

32 位地址空间分三大段：P0（代码/堆，向下长）、P1（栈，向上长）、S（内核，共享、映射进每个进程）。P0 和 P1 之间是空的。页 0 被标成"不可访问"，用来抓空指针。

```text
      0 +-----------------------------+
        |         页0: 无效           |
        +-----------------------------+
        |         用户代码            |
        +-----------------------------+ \
        |         用户堆              |   用户 (P0)
        +-----------------------------+ /
                  | (向下)
                  v
    2^30 +-----------------------------+ \
         |        (空白区域)           |   用户 (P1)
         |                             | /
                  ^ (向上)
         +-----------------------------+
         |         用户栈              |
    2^31 +-----------------------------+ \
         |         陷阱表              |
         +-----------------------------+ |
         |         内核数据            |   系统 (S)
         +-----------------------------+ |
         |         内核代码            | |
         +-----------------------------+ /
         |         内核堆              |
         +-----------------------------+
                  | (向下)
                  v
    2^32 +-----------------------------+  (未使用)
```

### 2. 页表与翻译

P0、P1 各一张页表（段页式），避免中间空白区占页表空间；用户页表放在内核虚拟内存里，内存紧时可换出。硬件管理 TLB，绕过多级查找。

### 3. 置换：分段 FIFO + 二次机会

硬件没有引用位，做不了 LRU。于是：每个进程有驻留集上限，超了按 FIFO 踢最早进的页；被踢的页进"二次机会列表"（干净页、脏页分开），原进程若再访问还能直接捞回来，省一次磁盘 I/O。脏页批量写盘，缓解 512 字节小页的寻道开销。

### 4. 延迟优化（Laziness）

- **延迟零页（Demand Zeroing）**：分配堆页时只标"不可访问"，第一次真正访问才分配物理页并清零，别为没用到的页白干活。
- **写时复制（COW）**：`fork` 时不拷贝页面，父子共享并标只读，谁先写谁才复制一份。省内存又省拷贝时间。

## 二、现代案例：Linux

Linux 继承了 VAX/VMS 的核心理念，再针对 64 位、大内存、高安全做了大量优化。

### 1. 地址空间

用户态和内核态分离（32 位以 0xC0000000 为界），内核空间映射进所有进程。内核地址又分两种：逻辑地址（直接映射物理内存前半，连续、不可换出，给 DMA 用）和虚拟地址（`vmalloc` 分配，虚拟连续物理不连续，给大缓冲区用）。

```text
32 位虚拟地址空间（4GB）

0x00000000 ┌──────────────────────────────┐
           │          用户空间            │  每个进程私有一份（3GB）
           │     代码 / 堆 / 栈           │  互相隔离，靠页表权限
           │                              │
0xC0000000 ├──────────────────────────────┤ ← 用户态/内核态分界线
           │          内核空间            │  映射进所有进程，共享同一份
           │ ┌──────────────────────────┐ │
           │ │ 逻辑地址（直接映射）      │ │  物理内存前 896MB 线性映射：
           │ │ 虚拟 = 物理 + 0xC0000000  │ │  虚拟连续 = 物理连续
           │ │ 连续、不可换出            │ │  给 DMA / 内核核心用
           │ ├──────────────────────────┤ │
           │ │ 虚拟地址（vmalloc 区）    │ │  虚拟连续、物理不连续
           │ │ 给大缓冲区用              │ │
0xFFFFFFFF └──────────────────────────────┘
```

- **逻辑地址**：内核启动后直接把物理内存前 896MB 线性映射到 `0xC0000000` 起，虚拟地址 = 物理地址 + 0xC0000000，换算就是加一个常数；连续、不可换出，DMA 等需要"物理连续"的场景用它。
- **虚拟地址**：`vmalloc` 分配，物理页可以东一块西一块，靠页表拼成虚拟连续，给那些"虚拟要连续、物理无所谓"的大缓冲区用。

### 2. 多级页表

32 位二级、64 位四级（只用低 48 位），靠 PGD→PUD→PMD→PT 逐级索引，适配 TB 级内存。x86 硬件做页表查找，OS 只管维护结构、切换时更新基址寄存器。

```text
32 位地址：二级页表
┌──────────────┬──────────────┬────────────┐
│ 页目录索引    │ 页表索引      │ 页内偏移    │
│   10 位      │   10 位      │   12 位    │
└──────────────┴──────────────┴────────────┘
       31:22          21:12          11:0

64 位地址：四级页表（只用低 48 位，高 16 位不用）
┌────────┬────────┬────────┬────────┬────────┬────────────┐
│ 未使用  │  PGD   │  PUD   │  PMD   │   PT   │  页内偏移    │
│ 16 位  │  9 位  │  9 位  │  9 位  │  9 位  │   12 位    │
└────────┴────────┴────────┴────────┴────────┴────────────┘
  63:48    47:39    38:30    29:21    20:12    11:0
```

- 每级索引 9 位，正好索引一张 **512 项**的页表（2⁹=512），页大小 4KB（offset 12 位）。48 位 = 9×4 + 12，所以是四级。
- 查找链：**CR3（基址寄存器）→ PGD → PUD → PMD → PT → 物理页**。每一级都用"上一级查出的物理页框号 + 本级索引"定位下一级，最后拼上 offset 拿到物理地址。
- 每级表项 8 字节、512 项正好占一页（4KB），所以每一级本身都是一页，硬件顺着这条链一页一页查下去。

具体怎么"跳"，拿一个手算例子看（64 位地址、页 4KB，低 48 位 = 4 级 × 9 位 + offset 12 位）：

```text
[ PGD 索引 9位 ] [ PUD 索引 9位 ] [ PMD 索引 9位 ] [ PT 索引 9位 ] [ offset 12位 ]

虚拟地址 0x0000_0A1C_2F38_4ABC 拆成:
  PGD=0x0A1(161)   PUD=0x0C2(194)   PMD=0x0F3(243)   PT=0x184(388)   offset=0xABC

  CR3 = 0x1800            ← CR3 存 PGD 表的物理地址
    │
    ▼  用 PGD=161 当下标，取 PGD 表第 161 项
  PGD表 [161] = 0x2000     ← 该项存"下一级 PUD 表"的物理地址
    │
    ▼  用 PUD=194 当下标，取 PUD 表第 194 项
  PUD表 [194] = 0x3000     ← 该项存"下一级 PMD 表"的物理地址
    │
    ▼  用 PMD=243 当下标，取 PMD 表第 243 项
  PMD表 [243] = 0x4000     ← 该项存"下一级 PT 表"的物理地址
    │
    ▼  用 PT=388 当下标，取 PT 表第 388 项
  PT表 [388] = 0x5A000     ← 该项存"数据所在物理页框" PFN
    │
    ▼
  物理地址 = 0x5A000 + 0xABC = 0x5AABC
```

每一级干的都是同一件事：用"虚拟地址里对应的那几 bit"当下标，从"当前这张页表"里读出"下一级页表的物理地址"；只有最后一级（PT）读出的才是数据真正所在的物理页框，再拼上 offset 得到最终物理地址。表项里除了这个地址，还带有效位、读写执行权限、是否在内存等标志位。

**层数怎么算（通用公式）：**

- `offset 位数 = log₂(页大小)`
- `VPN 位数 = 地址位数 − offset 位数`
- 各级索引位数之和 = VPN 位数，层数就是把 VPN 再劈成几段
- 第 i 级条目数 = `2^(该级索引位数)`，该级表大小 = 条目数 × 表项大小
- TLB miss 的额外访存次数 = **层数**（每级都要查一次内存）

| 属性 | 二级页表（32 位 x86） | 三级页表（PAE，32 位+36 位物理） | 四级页表（x86-64，48 位） |
|------|----------------------|--------------------------------|--------------------------|
| 虚拟地址位数 | 32 | 32 | 64（只用低 48） |
| 页大小 | 4KB | 4KB | 4KB |
| offset 位数 | 12 | 12 | 12 |
| VPN 位数 | 20 | 20 | 36 |
| 各级索引划分 | 10 + 10 | 2 + 9 + 9 | 9 + 9 + 9 + 9 |
| 每级条目数 | 2¹⁰ = 1024 | 4 / 512 / 512 | 四级都是 512 |
| 表项大小 | 4B | 8B | 8B |
| 每级表大小 | 1024×4B = 4KB | 512×8B = 4KB | 512×8B = 4KB |
| 虚拟页数 | 2²⁰ ≈ 100 万 | 2²⁰ ≈ 100 万 | 2³⁶ ≈ 680 亿 |
| 可寻址空间 | 4GB | 4GB（物理到 64GB） | 256TB |
| TLB miss 额外访存 | 2 次 | 3 次 | 4 次 |

规律：地址位数越大、页越小 → VPN 位数越多 → 层数越多。层数越多，单次未命中越慢（多查几次内存），但稀疏地址空间越省——只为真正用到的那些分支建表，中间大片空洞的页表页压根不分配。

### 3. 大页（THP）

4KB 小页太小：一条 TLB 条目只覆盖 4KB，128 条 TLB 总共才覆盖 512KB，进程工作集一旦超过它，TLB 就疯狂未命中。把页变大，同样一条 TLB 条目覆盖的内存暴增：

| 页大小 | 单条 TLB 覆盖 | 128 条 TLB 总共覆盖 |
|--------|--------------|--------------------|
| 4KB | 4KB | 512KB |
| 2MB | 2MB | 256MB |
| 1GB | 1GB | 128GB |

```text
4KB 页:   TLB 一页一页装 [4KB][4KB][4KB]…，128 条才 512KB，大工作集装不下
2MB 大页: 一条顶 512 个 4KB 页，[2MB][2MB]… 覆盖 256MB，命中率大涨
```

Linux 两种大页：

- **显式大页**：`mmap(MAP_HUGETLB)` / `shmget` 显式申请 2MB/1GB，应用要主动配合；
- **透明大页（THP）**：OS 后台自动把连续的 4KB 页合成 2MB，应用不用改一行代码。

好处是省 TLB 条目、降未命中；代价是两个——2MB 页内哪怕只用 1KB 也占一整页（内部碎片），而且大页不好 swap 出磁盘。

### 4. 页缓存与置换

**统一页缓存**：Linux 只有一张大缓存，装所有"页"，不管它是文件页还是匿名页：

- 内存映射文件（`mmap` 的文件）、`read`/`write` 读写的文件内容、匿名内存（堆/栈，本来没有文件对应）——统一按"页"管理，用哈希表按"文件 + 偏移"快速定位。

**置换用 2Q（两个队列）**：把页分成"活跃"和"非活跃"两个列表。

```text
         首次访问                       再次访问（说明是热页）
   新页 ─────────→ 非活跃列表(inactive) ──────────→ 活跃列表(active)
                      │                                 │
  内存不够时先踢这里 ──┘（冷页、只碰一次的页）             └─ 热页，最后才动
```

- 页刚进来只进**非活跃**列表；之后**再次被访问**才晋升到**活跃**列表；
- 内存紧张时**优先踢非活跃**列表里的页——那里都是"只碰过一次"或不常碰的冷页。

这招专防"大文件顺序扫描"：`cat 一个大文件` 会把文件页逐个读一遍，但这些页读一次就再也不碰，一直待在非活跃列表；内存一紧，先被踢的是这些冷页，活跃列表里真正的热页（进程代码、常用数据）不受波及。脏页由 `pdflush`（现在的内核 worker 线程）后台定期批量写盘，不用等被踢时才写。

### 5. 安全特性

- **NX 位（不可执行）**：页表项里加"不可执行"位，把栈、堆标成"只读+写、不可执行"。
  - 防缓冲区溢出注入：攻击者把 shellcode 写进栈缓冲区、再让程序跳过去执行。有 NX 后，栈/堆上的代码一执行就触发异常。
  - 一句话：让"数据区"永远当不了"代码区"。

- **ASLR（地址空间布局随机化）**：每次启动进程，把代码、堆、栈、共享库的基地址随机偏移。
  - 防 ROP（返回导向编程）：攻击者不注入代码，而是复用程序里现成的指令片段（gadget）拼攻击链，前提是必须知道这些 gadget 的地址。ASLR 让地址每次运行都变，攻击者猜不准。
  - 前面作业里连续读同一进程的 `[heap]`/`[stack]` 地址每次不同，就是 ASLR 在起作用。

- **KASLR（内核地址随机化）**：把 ASLR 用到内核自己身上，内核符号和数据地址随机化，增加内核漏洞利用难度。

- **KPTI（内核页表隔离）**：本来为了省切换开销，用户进程的页表常年映射着整个内核空间。KPTI 拆成两张——用户态只保留极少数必需的内核映射，其余内核地址只在真正进内核时才可见。
  - 防 Meltdown 这类侧信道：利用 CPU 乱序执行提前偷读内核内存。KPTI 让用户态压根映射不到那些内核地址，从根上断了这条路。
  - 代价：用户/内核切换要换页表，syscall 性能略降。

## 三、VAX/VMS vs Linux

| 特性 | VAX/VMS（经典） | Linux（现代） |
|------|-----------------|---------------|
| 地址空间划分 | 进程空间 + 共享内核 | 相同逻辑，适配 32/64 位 |
| 核心优化 | 延迟零页、COW、聚类写 | 继承经典，新增 THP、统一页缓存 |
| 置换策略 | 分段 FIFO + 二次机会 | 改进 2Q（近似 LRU） |
| 安全重点 | 基础内核/用户隔离 | 防溢出、防 ROP、防侧信道 |
| 适配场景 | 中小型 VAX 机 | 手机、服务器、数据中心 |

## 四、核心组件总结

1. 地址空间：分用户/内核，支持稀疏，页 0 无效抓空指针；
2. 页表：多级/段页式省内存，支持换出；
3. 翻译加速：硬件 TLB + 大页；
4. 置换：平衡命中率和开销（2Q 应对大文件）；
5. 延迟优化：延迟零页、COW；
6. 存储协同：聚类写、统一页缓存；
7. 安全：NX、ASLR、KASLR、KPTI。

1. 对比测试：在Linux上启用/禁用ASLR/THP，观察应用启动速度、内存占用、TLB未命中频率；
2. 页缓存分析：使用vmstat/iostat工具，观察文件读写时页缓存的命中/未命中情况；
3. 大页性能测试：编写程序分别使用4KB页和2MB大页，对比内存访问带宽；
4. 安全验证：编写简单缓冲区溢出代码，观察NX位和ASLR对攻击的防御效果；
5. 置换策略模拟：基于2Q算法，模拟不同工作负载（随机访问、80-20负载）的命中率。

本章无模拟器，作业是 Linux 实操验证。本机观测结果：

### 1. ASLR / THP 状态

```shell
cat /proc/sys/kernel/randomize_va_space     # 2 = 完全随机化（开）
cat /sys/kernel/mm/transparent_hugepage/enabled   # [always] = 开
```

```text
randomize_va_space = 2
transparent_hugepage = [always] madvise never
```

验证 ASLR 真的在起作用——连续几次读同一进程的堆/栈地址，每次都变：

```text
[heap]  aaaae6f76000    [stack] ffffd0c1f000
[heap]  aaab0bdb1000    [stack] ffffc213c000   ← 每次运行都不同
[heap]  aaaaeff22000    [stack] ffffd4fcd000
```

### 2. 页缓存

```shell
free -m
```

```text
Mem:  62009 used 11664 free 11152 buff/cache 40308 available 50344
```

本机 `buff/cache` 约 40GB——这就是统一页缓存：文件读写、内存映射文件都被缓存着，内存不够时才回收。

### 3. 大页（THP）

```shell
cat /sys/kernel/mm/transparent_hugepage/enabled
grep -i huge /proc/meminfo
```

```text
[always] madvise never
AnonHugePages:    282624 kB   ← 已有 282MB 匿名内存被合成 2MB 大页
ShmemHugePages:        0 kB
FileHugePages:         0 kB
HugePages_Total:       0      ← 显式大页（hugetlb）没配
Hugepagesize:       2048 kB   ← 大页大小 2MB
```

`[always]` 表示 THP 默认开；`AnonHugePages` 282MB 说明内核真的在把连续匿名内存合成 2MB 大页（应用没改一行代码）。`HugePages_Total = 0` 表示没配显式大页（那要用 `mmap MAP_HUGETLB` 主动申请）。4KB vs 2MB 的带宽对比需写程序申请显式大页，这里验证的是 THP 状态 + 实际用量。

### 4. 安全（NX 位）

```shell
uname -m
grep -E "\[stack\]" /proc/self/maps
```

```text
aarch64
ffffd71e7000-ffffd7209000 rw-p 00000000 00:00 0   [stack]
```

直接看 `/proc/self/maps` 里 `[stack]` 那行的权限是 `rw-p`——只有读(r)、写(w)，**没有执行(x)**。这就是 NX 的落地证据：栈被标成不可执行，攻击者往栈里写的 shellcode 一旦跳过去执行就触发异常。

本机是 aarch64，`/proc/cpuinfo` 里没有 x86 的 `nx` flag，因为 ARM64 的执行禁止是**架构内置**的（PXN/UXN），不需要单独 CPU flag；但效果一样——栈/堆默认不可执行。

### 5. 置换策略（2Q）

```shell
grep -iE "active|inactive" /proc/meminfo
```

```text
Active:          4996000 kB
Inactive:       51049984 kB
Active(anon):     137904 kB
Inactive(anon): 14916684 kB
Active(file):    4858096 kB
Inactive(file): 36133300 kB
```

`/proc/meminfo` 里的 `Active`/`Inactive` 就是 2Q 那两条列表的实时计数：活跃列表 4.9GB、非活跃列表 51GB，还按来源分成 anon（匿名内存）和 file（文件页）。能直接看到"文件页的非活跃远大于活跃"（36GB vs 4.8GB）——大量只读一次的文件页待在非活跃列表，内存一紧就先踢它们，这正是 2Q 防"顺序扫描冲刷热页"的效果。

（`paging-policy.py` 没有 2Q 策略，只能拿 CLOCK 近似；真要模拟 2Q 的双列表晋升逻辑得自己写，用 `/proc/meminfo` 观察最直接。）
