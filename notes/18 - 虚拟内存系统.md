# 18 - 虚拟内存系统

前面各章是"零件"：分页、TLB、多级页表、置换策略。这一章把它们装成两台真实的机器——经典的 **VAX/VMS**（1970s-1980s）和现代的 **Linux**，看一个完整 VM 系统怎么把这些机制组合起来，还要兼顾性能、安全和复杂度。

## 一、经典案例：VAX/VMS

VAX/VMS 是早期 VM 系统的标杆，核心思路是"用软件创新弥补硬件缺陷"（比如它只有 512 字节小页、又没有引用位）。

### 1. 地址空间

32 位地址空间分三大段：P0（代码/堆，向下长）、P1（栈，向上长）、S（内核，共享、映射进每个进程）。P0 和 P1 之间是空的。页 0 被标成"不可访问"，用来抓空指针。

```text
      0 +-----------------------------+
        |         页0: 无效           |
        +-----------------------------+
        |         用户代码            |
        +-----------------------------+ \
        |         用户堆              |   用户 (P0)
        +-----------------------------+ /
                  | (向下)
                  v
    2^30 +-----------------------------+ \
         |        (空白区域)           |   用户 (P1)
         |                             | /
                  ^ (向上)
         +-----------------------------+
         |         用户栈              |
    2^31 +-----------------------------+ \
         |         陷阱表              |
         +-----------------------------+ |
         |         内核数据            |   系统 (S)
         +-----------------------------+ |
         |         内核代码            | |
         +-----------------------------+ /
         |         内核堆              |
         +-----------------------------+
                  | (向下)
                  v
    2^32 +-----------------------------+  (未使用)
```

### 2. 页表与翻译

P0、P1 各一张页表（段页式），避免中间空白区占页表空间；用户页表放在内核虚拟内存里，内存紧时可换出。硬件管理 TLB，绕过多级查找。

### 3. 置换：分段 FIFO + 二次机会

硬件没有引用位，做不了 LRU。于是：每个进程有驻留集上限，超了按 FIFO 踢最早进的页；被踢的页进"二次机会列表"（干净页、脏页分开），原进程若再访问还能直接捞回来，省一次磁盘 I/O。脏页批量写盘，缓解 512 字节小页的寻道开销。

### 4. 延迟优化（Laziness）

- **延迟零页（Demand Zeroing）**：分配堆页时只标"不可访问"，第一次真正访问才分配物理页并清零，别为没用到的页白干活。
- **写时复制（COW）**：`fork` 时不拷贝页面，父子共享并标只读，谁先写谁才复制一份。省内存又省拷贝时间。

## 二、现代案例：Linux

Linux 继承了 VAX/VMS 的核心理念，再针对 64 位、大内存、高安全做了大量优化。

### 1. 地址空间

用户态和内核态分离（32 位以 0xC0000000 为界），内核空间映射进所有进程。内核地址又分两种：逻辑地址（直接映射物理内存前半，连续、不可换出，给 DMA 用）和虚拟地址（`vmalloc` 分配，虚拟连续物理不连续，给大缓冲区用）。

### 2. 多级页表

32 位二级、64 位四级（只用低 48 位），靠 P1~P4 逐级索引，适配 TB 级内存。x86 硬件做页表查找，OS 只管维护结构、切换时更新基址寄存器。

### 3. 大页（THP）

4KB 小页在大内存下 TLB 不够用。Linux 支持显式大页（`mmap`/`shmget` 申请 2MB/1GB）和**透明大页（THP）**——OS 自动把连续区域合成大页，应用不用改。好处是省 TLB 条目、降未命中；代价是内部碎片、swap 表现差。

### 4. 页缓存与置换

统一页缓存，缓存三类数据：内存映射文件、文件读写数据、匿名内存（堆/栈），靠哈希表查找。置换用改进的 **2Q 算法**：活跃列表 + 非活跃列表，首次访问进非活跃，再访问才晋升活跃；置换优先踢非活跃，避免大文件顺序扫描"冲刷"掉有用页。脏页由 `pdflush` 后台线程定期写盘。

### 5. 安全特性

- **NX 位**：栈等区域标"不可执行"，防缓冲区溢出注入代码；
- **ASLR**：地址空间布局随机化，随机化代码/堆/栈地址，破 ROP（返回导向编程）攻击；
- **KASLR**：随机化内核地址，提升内核安全性；
- **KPTI**：内核页表隔离，减少用户态里的内核映射，防 Meltdown/Spectre，代价是切页表有开销。

## 三、VAX/VMS vs Linux

| 特性 | VAX/VMS（经典） | Linux（现代） |
|------|-----------------|---------------|
| 地址空间划分 | 进程空间 + 共享内核 | 相同逻辑，适配 32/64 位 |
| 核心优化 | 延迟零页、COW、聚类写 | 继承经典，新增 THP、统一页缓存 |
| 置换策略 | 分段 FIFO + 二次机会 | 改进 2Q（近似 LRU） |
| 安全重点 | 基础内核/用户隔离 | 防溢出、防 ROP、防侧信道 |
| 适配场景 | 中小型 VAX 机 | 手机、服务器、数据中心 |

## 四、核心组件总结

1. 地址空间：分用户/内核，支持稀疏，页 0 无效抓空指针；
2. 页表：多级/段页式省内存，支持换出；
3. 翻译加速：硬件 TLB + 大页；
4. 置换：平衡命中率和开销（2Q 应对大文件）；
5. 延迟优化：延迟零页、COW；
6. 存储协同：聚类写、统一页缓存；
7. 安全：NX、ASLR、KASLR、KPTI。

## 五、作业方向（实践）

1. 对比测试：在Linux上启用/禁用ASLR/THP，观察应用启动速度、内存占用、TLB未命中频率；
2. 页缓存分析：使用vmstat/iostat工具，观察文件读写时页缓存的命中/未命中情况；
3. 大页性能测试：编写程序分别使用4KB页和2MB大页，对比内存访问带宽；
4. 安全验证：编写简单缓冲区溢出代码，观察NX位和ASLR对攻击的防御效果；
5. 置换策略模拟：基于2Q算法，模拟不同工作负载（随机访问、80-20负载）的命中率。

本章无模拟器，作业是 Linux 实操验证。本机观测结果：

### 1. ASLR / THP 状态

```shell
cat /proc/sys/kernel/randomize_va_space     # 2 = 完全随机化（开）
cat /sys/kernel/mm/transparent_hugepage/enabled   # [always] = 开
```

```text
randomize_va_space = 2
transparent_hugepage = [always] madvise never
```

验证 ASLR 真的在起作用——连续几次读同一进程的堆/栈地址，每次都变：

```text
[heap]  aaaae6f76000    [stack] ffffd0c1f000
[heap]  aaab0bdb1000    [stack] ffffc213c000   ← 每次运行都不同
[heap]  aaaaeff22000    [stack] ffffd4fcd000
```

### 2. 页缓存

```shell
free -m
```

```text
Mem:  62009 used 11664 free 11152 buff/cache 40308 available 50344
```

本机 `buff/cache` 约 40GB——这就是统一页缓存：文件读写、内存映射文件都被缓存着，内存不够时才回收。

### 3. 大页（THP）

THP 显示 `[always]`，表示内核默认把连续匿名内存合成 2MB 大页，应用不用改。4KB 与 2MB 的带宽对比需申请显式大页（`mmap MAP_HUGETLB`），这里只验证开关状态。

### 4. 安全（NX 位）

本机是 aarch64，`/proc/cpuinfo` 里没有 x86 的 `nx` 标志——ARM64 的执行禁止是**架构内置**的（PXN/UXN，特权/用户执行禁止），无需单独 CPU flag。所以防溢出注入在 ARM64 上天然生效。

### 5. 置换策略（2Q）

2Q 的核心是"活跃/非活跃双列表"：首次访问进非活跃，再访问才晋升活跃；置换优先踢非活跃。可用 `paging-policy.py` 手动模拟近似行为，或读 `/proc/meminfo` 的 `Active/Inactive` 计数观察。
