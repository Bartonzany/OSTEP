# 10 - 内存地址转换

CPU 虚拟化靠"有限直接执行"，内存虚拟化也是一样的思路：让程序直接跑以保证效率，OS 只在关键节点介入。地址转换就是这个核心机制——每次程序访问内存时，硬件自动把它发出的虚拟地址翻译成真实物理地址，程序全程无感，还以为自己独占一块从 0 开始的私有内存。

先立三条简化假设（后面几章会逐个拆掉）：地址空间在物理内存里**连续**、地址空间**小于**物理内存、所有地址空间**一样大**。

![alt text](../assets/10_1-动态重定位.png)

## 一、动态重定位（基址 + 边界）

最简单的地址转换技术叫**动态重定位（Base-and-Bounds）**，靠两个 CPU 寄存器：

- **基址寄存器（Base）**：存这个进程地址空间在物理内存里的起始位置（也就是"偏移量"）。
- **边界寄存器（Bounds/Limit）**：存地址空间的大小，用来校验虚拟地址有没有越界。

### 地址转换公式

公式就一条：硬件每次访问内存时，把虚拟地址加上基址寄存器的值，得到物理地址。

```shell
物理地址 = 虚拟地址 + 基址寄存器值
```

拿一条具体指令追踪一遍最直观。假设地址空间 16KB（边界 = 16KB）、被加载到物理内存 32KB 处（基址 = 32KB），某条指令是：

```shell
128: movl 0x0(%ebx), %eax      ← 把 ebx 指向的内存地址里的值加载进 eax
```

执行它要访问两次内存，每次都走一遍上面的公式：

1. **取指令**：PC 先设为 128，加上基址 32KB（32768），得到物理地址 32896，硬件从这里把指令取回来；
2. **取数据**：指令执行时要加载虚拟地址 15KB 处的数据，同样加基址 32KB，得到物理地址 47KB，从那里读出数据。

程序全程以为自己在访问"128"和"15KB"这两个私有地址，硬件默默把它们加成了 32896 和 47KB——程序一行代码没改，这就是"动态重定位"。

那**边界（界限）寄存器去哪了**？它负责卡住越界访问：这个例子里边界 = 16KB，凡是虚拟地址 ≥ 16KB、或者为负的访问，CPU 直接触发异常、终止进程。没有它，程序就能顺着基址一路读写到别的进程甚至 OS 的内存里。所以翻译的完整流程其实是先检查、再加法：

```shell
if (虚拟地址 < 边界 && 虚拟地址 >= 0)
    物理地址 = 虚拟地址 + 基址
else
    触发异常（越界访问）
```

把上面几种访问列成一张表（地址空间 16KB，基址 32KB，边界 16KB）：

| 虚拟地址 | 计算 | 结果 |
|----------|------|------|
| 0KB | 0KB + 32KB | 32KB（合法） |
| 128B | 128B + 32KB | 32896B（合法，取指令） |
| 15KB | 15KB + 32KB | 47KB（合法，访问变量 x） |
| 17KB | 17KB ≥ 16KB | 异常（越界） |

### 对比：静态重定位

早期是软件方案：加载程序时由加载器把程序里所有地址直接改写成物理地址。没保护（程序能乱访问别的内存）、也搬不了家，后来被动态重定位取代。

## 二、硬件要提供什么

要让这套机制既快又受控，硬件得给：

| 硬件需求 | 作用 |
|----------|------|
| 特权模式（内核态/用户态） | 防止用户进程改基址/边界寄存器 |
| 基址-边界寄存器对 | 存物理起始位置和大小，每 CPU 一套 |
| 转换 + 边界检查电路 | 快速做虚拟地址→物理地址加法转换和合法性校验 |
| 改基址-边界的特权指令 | 只有内核态能改寄存器 |
| 异常处理程序注册指令 | OS 设置越界等异常的处理逻辑 |
| 异常触发机制 | 越界或用户执行特权操作时触发CPU异常 |

## 三、OS 要干什么

OS 负责"管理"，硬件负责"执行"：

| OS 职责 | 具体内容 |
|---------|----------|
| 内存管理 | 维护**空闲列表（Free List）**，跟踪物理内存中未使用的连续区域；<br>进程创建时从空闲列表分配连续物理内存，用于存储进程地址空间；<br>进程终止时回收该进程占用的物理内存，归还空闲列表 |
| 基址-边界寄存器管理 | 进程首次运行前，把地址空间的物理起始地址写入基址寄存器、大小写入边界寄存器；<br>上下文切换时，把当前进程的基址-边界值保存到 PCB，恢复待运行进程的值（每 CPU 仅一套寄存器，需按进程切换） |
| 异常处理 | 开机时注册异常处理程序（内存越界、非法特权操作）；<br>触发异常时终止违规进程、回收内存、清理相关数据结构（如进程表项） |
| 地址空间重定位（可选） | 进程未运行时，把其地址空间从物理内存一处复制到另一处，更新 PCB 中的基址值；进程恢复运行时经新基址转换，完全无感知 |



### 受限直接执行的时间线

下面两张图（原书 Table 15.4）把前面硬件/OS 的分工串成一条完整时间线，可以看到这套机制仍然走"受限直接执行"的老路——OS 启动时准备好机器，之后多数时间进程直接在 CPU 上跑、地址转换全由硬件完成、OS 不介入；只有进程行为不端时才插手。

按时间线捋一遍：

1. **开机**：OS 初始化陷阱表（告诉硬件异常/中断时跳到哪个处理程序）。
2. **运行进程 A 前**：OS 分配进程表项、分配物理内存、把 A 的基址/边界写进寄存器，再 return-from-trap 返回用户态。
3. **A 运行**：地址转换完全由硬件完成（加基址 + 边界检查），OS 不介入。
4. **时钟中断**：硬件保存 A 的寄存器、切到内核态、跳陷阱处理程序；OS 处理中断、调用 `switch()` 切到进程 B。
5. **B 运行**：硬件照常做地址转换。
6. **B 非法加载**：硬件触发异常、保存 B 的寄存器、切内核态；OS 介入，终止 B、回收它的内存、把它从进程表移除。

一句话：硬件负责"翻译 + 越界检查 + 触发中断/异常"，OS 负责"启动时设置好 + 出问题后清理"，平时进程自己直接跑。

## 四、优点与局限


- **高效性**：地址转换和边界检查都由硬件完成，只做一次加法和比较，几乎不影响程序运行效率；
- **透明性**：程序一行代码都不用改，仍然以为自己地址空间从 0 开始，完全感知不到转换过程；
- **保护性**：边界检查严格限制访问范围，防止进程非法访问其他进程或 OS 的内存；
- **灵活性**：支持动态重定位，OS 可以随时调整进程在物理内存中的位置（搬完改基址即可）。

局限是**内部碎片（Internal Fragmentation）**：地址空间要连续分配，但程序往往用不满整块空间，栈、堆之间的空隙就浪费了。比如分配了 16KB 的地址空间，栈和堆只占一部分，剩下的都是碎片。


## 五、总结

1. 地址转换是内存虚拟化的核心，靠硬件（基址-边界寄存器、转换电路）和 OS 协作，动态完成虚拟地址→物理地址。
2. 基址-边界是最简单的地址转换技术，高效、透明、有保护，但存在内部碎片。
3. 逻辑上延续"有限直接执行"：硬件做高效转换和检查，OS 做分配、寄存器管理、异常处理。
4. 后续章节会放松假设，引入分段、分页，解决内部碎片和灵活分配的问题。

1. 基于不同随机种子，判断虚拟地址是否合法，并计算合法地址的物理地址；
2. 确定边界寄存器的最小取值，确保所有生成的虚拟地址均合法；
3. 在给定边界值与物理内存大小的情况下，计算基址寄存器的最大允许值；
4. 分析边界寄存器值与随机生成虚拟地址合法性的比例关系，绘制图表。

### 1. 不同种子的地址转换

```shell
./relocation.py -s 0 -c
./relocation.py -s 1 -c
./relocation.py -s 2 -c
```

```shell
Base-and-Bounds register information:
  Base   : 0x00003082 (decimal 12418)
  Limit  : 472

Virtual Address Trace
  VA  0: 0x000001ae (decimal:  430) --> VALID: 0x00003230 (decimal: 12848)
  VA  1: 0x00000109 (decimal:  265) --> VALID: 0x0000318b (decimal: 12683)
  VA  2: 0x0000020b (decimal:  523) --> SEGMENTATION VIOLATION
  VA  3: 0x0000019e (decimal:  414) --> VALID: 0x00003220 (decimal: 12832)
  VA  4: 0x00000322 (decimal:  802) --> SEGMENTATION VIOLATION
```

规则就一条：先看 `VA < Limit`，过了就 `PA = VA + Base`，否则越界异常。比如 VA 430 < 472 → 430 + 12418 = 12848；VA 523 ≥ 472、VA 802 ≥ 472 就直接报 VIOLATION。

```shell
Base-and-Bounds register information:

  Base   : 0x0000363c (decimal 13884)
  Limit  : 290

Virtual Address Trace
  VA  0: 0x0000030e (decimal:  782) --> SEGMENTATION VIOLATION
  VA  1: 0x00000105 (decimal:  261) --> VALID: 0x00003741 (decimal: 14145)
  VA  2: 0x000001fb (decimal:  507) --> SEGMENTATION VIOLATION
  VA  3: 0x000001cc (decimal:  460) --> SEGMENTATION VIOLATION
  VA  4: 0x0000029b (decimal:  667) --> SEGMENTATION VIOLATION
```

换个种子 `-s 1`，随机出 Base=13884、Limit=290，规则完全一样：VA 261 < 290 → 261 + 13884 = 14145；VA 782 ≥ 290 → VIOLATION。种子只改变随机出的基址/边界/虚拟地址，判定规则不变。

### 2. 让所有虚拟地址都合法的边界最小值

虚拟地址是 `[0, asize)` 内随机生成的，最大值只会到 asize−1。要"无论生成什么 VA 都合法"，边界下限就是 **asize**（保证任何 VA < asize 恒成立）。`-a 1k` 时取 `-l 1k`：

```shell
./relocation.py -a 1k -l 1k -s 0 -c
```

```shell
  Limit  : 1024
  VA  0: 0x00000308 (decimal:  776) --> VALID: 0x00003913 (decimal: 14611)
  VA  1: 0x000001ae (decimal:  430) --> VALID: 0x000037b9 (decimal: 14265)
  VA  2: 0x00000109 (decimal:  265) --> VALID: 0x00003714 (decimal: 14100)
  VA  3: 0x0000020b (decimal:  523) --> VALID: 0x00003816 (decimal: 14358)
  VA  4: 0x0000019e (decimal:  414) --> VALID: 0x000037a9 (decimal: 14249)
```

所有 VA 都 < 1024，全部 VALID。

### 3. 基址寄存器的最大允许值

地址空间末尾 `Base + Limit` 不能超出物理内存，所以 **Base_max = 物理内存大小 − Limit**。默认物理内存 16k（16384）、Limit 取 100 时，Base 最大 = 16284。模拟器也校验这个——把 Base 设成 16285 就直接报错：

```shell
./relocation.py -p 16k -b 16284 -l 100 -s 0 -c    # 恰好贴合：16284 + 100 = 16384
./relocation.py -p 16k -b 16285 -l 100 -s 0 -c    # 超界：16285 + 100 = 16385
```

```shell
Base + Limit: 16385   Psize: 16384
Error: address space does not fit into physical memory with those base/bounds values.
```

### 4. 边界值越小，合法比例越低

理论上合法地址的比例 ≈ `Limit / asize`（VA 均匀落在 `[0, asize)`）。用 `-n 1000` 大量抽样就能看清这条关系：

```shell
./relocation.py -a 1k -l 256 -s 0 -n 1000 -c   # 边界 = 256（asize 的 1/4）
./relocation.py -a 1k -l 512 -s 0 -n 1000 -c   # 边界 = 512（asize 的 1/2）
```

```shell
-l 256: VALID=247   VIOLATION=753   （约 25% 合法，正好 ≈ 256/1024）
-l 512: VALID=508   VIOLATION=492   （约 50% 合法，正好 ≈ 512/1024）
```

边界划在哪，合法地址的比例就约等于 `Limit/asize`——这条"边界线"把多大比例的虚拟地址挡在外面，一目了然。
